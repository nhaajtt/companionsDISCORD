Devlog

How this project was built, version by version. It includes the parts that went wrong and were fixed, because that is where most of the learning was.

D-01

Version 1: a few small bots

It started with a simple idea
make the chat less empty

  1. Split out of the music bot

    The companions were born inside the music bot's repo, because the idea came up there: a server with a music bot can still feel empty between songs. A few days later they moved to their own project. They share nothing at runtime, someone who only wants lively chat should not have to download a music bot, and the two repos can be updated or rolled back separately. On the Raspberry Pi they are just two folders and two containers.

  2. Manners before jokes

    One channel only, quiet hours, a daily limit, and stepping back when people are talking. The bots do not read message content: knowing that someone wrote something is enough.

  3. Bots stay bots

    They keep the BOT tag, never pretend to be human and never claim to eat, sleep or travel. Making a server feel alive is fine; pretending to be people is not.

D-02

Version 2: they can play

Ask, quiz, vote
and see who joins in

  1. Question of the day, polls, trivia

    A question at a fixed hour, real Discord polls, trivia with answer buttons and a weekly board. Each server can add its own questions, jokes and facts with a command.

  2. Measuring whether it helps

    /companions stats shows how many conversations actually got people talking. If the bots only talk to themselves, you should know.

  3. Timing is the hard part, not the jokes

    The first tests used time windows that were too short, so a punchline test passed for the wrong reason. Moving the clock in small steps and asserting who speaks when (and who does not) was far more honest. Another bug: a person's message in the exact millisecond a conversation began was not counted as joining in; comparing with >= fixed it.

D-03

Version 3: sitting with people

Present 24/7
even when everyone has left

  1. Voice is a reconcile loop

    Reacting to every disconnect event gets messy (Discord moves bots between voice servers, kicks, restarts). Instead every 15 seconds a bot compares what should be true (saved room, number of bots) with what is true and repairs it, waiting longer after failed joins. Restarting the container restores the room; I checked that on the Pi.

  2. Several rooms, sticky bots

    Each room remembers its own bots: new or bigger rooms only use free ones. At first I re-dealt everything whenever a room changed and bots were pulled out of other rooms. The complaint was fair.

  3. The "+ New Channel" loop

    A create-a-room channel made each bot spawn its own room and keep rejoining the original. Now the bots learn the room that was created, share it and no longer go back to the creator channel.

  4. Tools around the room

    A greeting when someone joins, Pomodoro, a voice time board, a welcome for new members (reading the system message type instead of asking for a special intent), reminders and event countdowns. Anything holding user IDs got its own erase command and a line in the "What is stored" table.

D-04

Version 4: safe to leave alone

Nobody watching
and it still has to be reliable

  1. A tick must never overlap itself

    With many servers and slow voice joins one round could outlast the 15 second timer and a second one would start on top of it, joining the same bot twice. Each loop now skips a round while the last one still runs.

  2. Learning from usage, carefully

    Adaptive tuning multiplies the default weights by how well each kind engages in that server, bounded to half and double, pulled toward the average while data is thin, and off until 20 conversations exist. Because it can be explained in one sentence, it can be reported in /companions stats.

  3. A measurement instead of a guess

    300 simulated servers for 8 hours: the slowest tick took about 30 ms, memory grew a few tens of MB, every server stayed inside its daily cap.

  4. Alerts and backups

    An optional webhook tells you when a bot loses its login or cannot rejoin voice, and the data files are backed up daily with 7 copies kept. Per-server data export and delete, and an automatic clean-up a day after the last bot leaves a server.

  5. Secrets in tests

    A test that wanted a token-shaped string was blocked by GitHub push protection. The string is now built from pieces; the warning was not bypassed.

D-05

Version 4.x: thirty personalities

From nine to thirty
each bot with its own voice

  1. From 10 to 30 bots

    21 new personalities, each with its own lines and 25 funny notes under its name in each language. Logging in a few bots at a time and lighter caches keep 30 bots small: with 23 running, a Raspberry Pi 5 sits at about 5% CPU and 113 MB of RAM.

  2. furyZ and Chamy

    A pair of bots: furyZ is a Valorant gamer and Chamy is his girlfriend, with matching couple notes.

  3. Thousands of lines

    About 1,000 lines per language for each purpose: welcoming a new member, greeting in the voice room, saying goodbye, reminders, and 500 for each step of a focus session. After that every personality speaks in its own voice, 20 lines per purpose.

  4. 1,259 trivia questions per language

    About 960 new questions in 20 topics, each with four options. A second reader checked every question, 20 doubtful ones were dropped, and I read a random 70 myself.

  5. A small bug worth remembering

    A command description over Discord's 100 character limit crashed a deploy during command registration. Checking command descriptions is now part of CI and runs before every deploy.

D-06

The website

A static page
with some cinema

  1. From a static page to an experience

    A field of orbs that follow the pointer, a kinetic headline, a pinned story scene when scrolling and a trivia game you can play on the page. It is plain HTML, CSS and JS, respects reduced motion, comes in two languages and was checked in a real Chrome at several screen sizes.

D-07

Still open

Honestly
what is not done

  1. Not watched for long on a real server

    It has run on the Pi with real bots and real voice rooms, but the notes under the names, goodbyes, weekly recap, trivia streaks and seasonal packs were mostly tried with fakes. A few days of watching would tune the pacing and content.

  2. Only English and Vietnamese

    Another language means another content bank and a parity test.

  3. The bots do not answer what you wrote

    That would need a language model behind them, with its cost and content safety questions, and it would break the promise of not reading messages. Not planned.

  4. No live streaming

    A bot cannot stream like a user; that would need an automated user account, which Discord forbids. Each bot has a funny note under its name instead.

D-08

The project is finished

Version 4.3
complete

The project stops at version 4.3: 30 personalities, 84 passing tests, docs and website up to date, running on one Raspberry Pi. The source is open, so anyone can run their own. I am stopping here to move on to other things, not because the ideas ran out.
