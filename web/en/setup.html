Setup

One command, or step by step if you like doing things yourself. You need somewhere to run 24/7, such as a Raspberry Pi.

S-01

The quick way: one command

On a Raspberry Pi or Debian
run it top to bottom

The one-command installer is for a Raspberry Pi or a Debian machine. It is safe to run again.

curl -fsSL https://raw.githubusercontent.com/nhaajtt/companionsDISCORD/main/scripts/install-pi.sh | sh

To preview what it would do, run sh scripts/install-pi.sh --dry-run (from a clone of the repo). Add --timer to install the daily auto-update. If you want to control each step, or you are on another machine, follow the manual steps below.

S-02

The manual way, step by step

Work through in order
no privileged intents needed

  1. Create 2 to 10 applications

    Open the Discord Developer Portal, create one application per bot, add a Bot to each and copy its token. No privileged intent is needed. The more bots, the livelier.

  2. Invite every bot to your server

    Use this link, replacing CLIENT_ID with that bot's Application ID (permissions: View Channel, Send Messages, Read Message History, Send Polls, Connect).

    https://discord.com/oauth2/authorize?client_id=CLIENT_ID&scope=bot%20applications.commands&permissions=562949954538496

    Bots you invited earlier need the Connect permission added (edit the role, or invite them again with this link) before they can sit in a voice room.

    With several bots, use the invite helper: paste the Application IDs and get one click per bot.

    Use the invite helper

  3. Fill in the .env file

    Copy .env.example to .env and put the tokens in, comma-separated. The first token is Pip, the second is Grumble, and so on.

    cp .env.example .env
    COMPANION_TOKENS=token1,token2,token3
COMPANION_TIMEZONE=Asia/Ho_Chi_Minh

  4. Run it

    With Docker (it publishes no ports):

    git clone https://github.com/nhaajtt/companionsDISCORD.git && cd companionsDISCORD
docker compose up -d --build

    Without Docker (needs Node.js 20 or newer):

    npm install && npm start

  5. Pick the channel

    In Discord, run the command below. The first bot hosts the command, and you need the Manage Server permission.

    /companions setup channel:#general language:English

S-04

Make it your own

Your jokes, your rules
no redeploy needed

Managers can teach the bots your server's in-jokes with the content commands: add-question, add-joke, add-fact and add-poll. Each server can hold up to 100 entries of each kind, and any pings in them are stripped, so nobody gets @everyone'd by a joke. Use content list to see what you added and content remove to take an entry back. /companions toggle switches trivia rounds or polls on and off.

Your entries live in data/custom.json. To change the built-in banks instead, edit the files in src/content/ (see the FAQ).

S-05

What is stored

Six files in data/
all on your own machine

FileHolds
companions.jsonPer-server settings: channel, language, frequency, quiet hours, question of the day, trivia and poll switches
usage.jsonDaily counters only (how many conversations of each kind were started and engaged). No messages, no user ids
custom.jsonThe questions, jokes, facts and polls your managers added
scores.jsonUser data: the Discord user ids of people who got a trivia answer right, with their points per week. /trivia forget erases a person's entries
voice.jsonMinutes people spent in the voice room the companions sit in: user ids with minutes per week. /voice forget erases a person's entries
reminders.jsonWaiting reminders and event countdowns: the text typed and the author's user id. Deleted once delivered or cancelled

User ids live in scores.json, voice.json and reminders.json and nowhere else. No message is ever stored, and nothing leaves your machine. More on the privacy page.

S-07

FAQ

Questions people ask
and a few nobody does

Do the bots read my messages?

No. They only use the non-privileged Guilds, GuildMessages and GuildVoiceStates intents, to notice that someone wrote, replied or joined the voice room. They never read or store the content.

Do they pretend to be human?

No. They keep Discord's BOT tag, have nine distinct personalities and run on normal bot tokens, never a user account.

Can they run next to the music bot on one Raspberry Pi?

Yes. Separate folders, separate containers, and nothing shared at runtime. See the table above.

How do I add my own jokes?

Managers can use /companions content add-joke (or add-question, add-fact, add-poll), see above. To change the built-in banks, add entries to src/content/en.js or src/content/vi.js (the tests check the shape of every entry). Adding a language means a new file in src/content/ and a line in src/content/index.js and src/settings.js.

Where is my data kept?

In six files in data/ on your own machine: per-server settings, daily usage counters (no messages, no user ids), the content your managers added, trivia scores, voice minutes and waiting reminders. User ids are kept only in scores.json, voice.json and reminders.json, and each person can erase their own with /trivia forget and /voice forget (reminders are deleted once delivered or cancelled). The details are on the privacy page.

How do I add the bots to another server later?

Open the invite helper, paste the Application IDs and invite each bot to the new server (invite the first bot first). Or run npm run invites in the project folder: it prints every invite link and a bookmark link for the helper, read from .env right on your machine.
